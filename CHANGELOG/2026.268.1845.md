# 2026.268.1845 — feat(fleet): thread ctx to member bring-up/teardown + member persist

## Summary of changes

Adopt `sdk v0.2026268.1823` + `spec v0.2026268.1800`, whose
`deploykit.BringUpMembers` / `TearDownMembers` / `PersistBedDeployOverrides` now
require a `context.Context` carrying the invocation's per-invocation RunEnv
(plan §4.2 / F8; RCA issue 7). The operator deploy path threads `cmdCtx`
(no RunEnv → the child inherits the parent env unchanged), so operator behavior is
identical; the ctx is what lets a concurrent in-process check-bed roster's member
forks write the **bed's** overlay, never the operator's real
`~/.config/charly/charly.yml`.

### What changed
- `walk.go` — `DeployAddCmd.Run` passes `cmdCtx` to `persistMemberDeployOverrides`
  and `deploykit.BringUpMembers`; `DeployDelCmd.Run` passes `cmdCtx` to
  `deploykit.TearDownMembers`.
- `members_persist.go` — `persistMemberDeployOverrides` takes `ctx` and forwards it
  to `deploykit.PersistBedDeployOverrides`.
- `bed_persist_writer_test.go` — call sites updated for the required ctx.

**Closes / relates to:** plugin-fleet leg of the check-bed-roster cutover (plan §4.2).
Depends on sdk#287 (merged, tagged `v0.2026268.1823`).
