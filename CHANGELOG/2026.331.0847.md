### The compile break the bump surfaced, and its RCA (R1)

The first `go vet ./...` after the bump failed, while `go build ./...` passed:

```
# github.com/opencharly/plugin-fleet/candy/plugin-fleet
vet: ./deploy_target_test.go:115:9: undefined: spec.ApkInstallStep
```

- **Mechanism**: spec `v0.2026331.808` deletes `ApkInstallStep` (the android app-install IR step) from the step vocabulary. The repo's own `prepareReverseState` guard test used that type as its "carries no home token and no ServicePackaged probe" fixture, so type-checking the test package failed. `go build` compiles no test files, which is why it stayed green.
- **Missed control**: the bump was taken before diffing the new contract's symbol set against the repo's references. The check that would have caught it a step earlier is a symbol diff of the new module (`grep -rn 'android'` over the pinned module returns nothing; `grep -rn 'ApkInstallStep'` over the old module shows the deletion) before the `go get`.
- **Blast radius**: one test fixture. No production code path referenced the type.
- **Root fix**: the fixture now uses `spec.SystemPackagesStep` — a live, non-home, non-service step — so the guard's claim ("a plan with no home token and no ServicePackaged step pays no venue `ResolveHome` exec") is still asserted by the same test, without a retired type.

It is fixed in this change, not filed.
