# 2026.318.2345 — fix(deploy): the import success line counts ENTRIES, not files

## Summary

**Successor of #49** (auto-closed by the review policy after five verdicts — a policy action, not a code
finding). This is ONE clean commit on a fresh branch off `origin/main`, carrying every fix that thread produced;
the findings it raised are all addressed below.

Second half of sdk#517 (Refs #48). `charly deploy import` reported success over an import that landed
nothing, because its success line counts FILES:

```
$ charly deploy import /tmp/openwebui-lab.yml
Imported 1 file(s) into /home/atrawog/.config/charly/charly.yml     # 1 file read, 0 entries landed
```

The loader half (sdk#517, merged as sdk#522, tag `v0.2026318.2225`) fixed WHY nothing landed — it reads the
name-first shape charly actually writes, and refuses a file that carries no deploy entry. This half fixes what
the verb SAYS:

```
Imported <n> entry|entries from <m> file(s) into <path>
```

* `n` is `len(dc.Deploy)` summed across the inputs — what was imported, not how the operator grouped it;
* `--box` narrows the import to one entry, so the count is 1;
* singular/plural is chosen for the count (a one-entry import must not read "1 entries");
* a nil or empty input contributes zero and does not panic.

`require github.com/opencharly/sdk` advances to `v0.2026318.2225` — the loader half is what makes the count
mean something, so the consumer adopts it in the same change.
