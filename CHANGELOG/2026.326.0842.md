# 2026.326.0842 — feat(builders)!: the deploy pre-pass uses the one builder rule and the one collect input

## Summary

The deploy pre-pass now uses the ONE builder rule and the ONE collect-input constructor (opencharly/sdk#608).

- `preresolveBuilderContexts` detects what the image needs through `deploykit.DetectExternalizedBuilders(order, candies, img)` — the same `NeedsBuilder` rule the render and the apply compile use — and the separate `externalized` word set and the nil-`BuilderConfig` `continue` are gone.
- The per-candy gate is `deploykit.NeedsBuilder`, so an arch-tagged `aur` declaration never reaches a fedora deploy.
- The collect input comes from `deploykit.BuilderCollectInputFor`, the one constructor (the golden-compile tool uses it too), replacing the hand-built input with its `DetectConfig`/`replaces` block.
- The builder plugin's declared package output (`BuilderCollectReply.Package`) is carried onto `BuilderPreresolved.Package`, which is what the apply compile installs through `local_pkg`.

**Also in this change.**

Two behaviour changes ship alongside the builder work, plus test-only adaptations:

- `from_box_vm.go`: `extractVmBoxDisk` now RETURNS a close error on the written disk. A failed close is a short or lost write, and it used to be dropped. The deferred close is one helper, `closeInto`, and `TestCloseIntoReportsAFailedClose` pins all three outcomes — reported against the destination, not masking an earlier error, and clean when the close succeeds; the mutation that drops the error fails it.
- `builder_scripts_test.go`: the aur builder script fixture drops the `/home/user/.cache/yay` and `/root/.cache/yay` fallback search and replaces its `|| true` with a zero-output guard that fails the build when `yay` produced no `.pkg.tar.zst` for a non-empty `aur:` package list. It also writes into the candy's own package directory (`{{.PkgDir}}`) instead of one shared `/tmp/aur-pkgs`. The fixture mirrors the aur stage template the sdk kit renders (sdk#613), so it moved with that pin; charly's own vocabulary entry is moved to the same shape in this chain's charly leg (charly#963).
- Test-only: a new `isolateHome` helper, and the mechanical adaptations the new sdk API forces (`rawbody.Encode`, `def.Fields()`, `BuildDepPkgsOnHost`'s signature, `TagSections`).
