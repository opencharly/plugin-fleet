# 2026.309.1933 — fix(deploy): adopt the engine-carrying deploy-state patch

## Summary

`plugin-fleet` is the compiled-in `command:deploy` plugin: it decodes a
`PrepareVenue` reply's opaque state patch into its OWN pinned
`spec.SaveDeployStateInput` before handing it to sdk's `SaveDeployState`.
opencharly/spec#292 added the authored `engine:` selector to that struct, and
opencharly/sdk#487 made `applyDeployState` write it; an older pin here would
silently drop the field between the pod plugin and the per-host entry.

This PR adopts `spec v0.2026309.1917` and `sdk v0.2026309.1926`, and adds an
end-to-end test (`TestSaveDeployState_PersistsEngine`) that drives the real
save path — this module's marshal/load callbacks + sdk's apply — and asserts
`engine: containerd` lands on the entry alongside `resolved_image`. It fails on
the pre-bump pins (measured below), so it is not a vacuous pass.

This is the consumer leg of opencharly/charly#1109; the live `pod:` /
`engine: containerd` bed is run in the `plugin-deploy-pod` and charly PRs that
follow the producer-first order.
