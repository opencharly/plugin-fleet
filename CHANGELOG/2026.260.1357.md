# 2026.260.1357 — fix(from-box): write the name-first kind:vm node, not the removed top-level vm: map

## Summary

`charly deploy from-box vm:<ref>` (`writeVmBoxEntity`) appended a **top-level `vm:` map** to
`charly.yml` — the named child-node shape **deleted** by the schema-compaction cutover. The
loader HARD-REJECTS it:

```
charly: error: ... node "vm": no kind discriminator — collections and plan steps live INLINE
in the kind value; run: charly migrate
```

So a VM authored by `from-box` produced a config that could never load. This is the
**same-mechanism sibling** of the `plugin-vm` `charly vm import` fix
(`opencharly/plugin-vm#35`), which had the identical defect.

### Fix

Emit the name-first node `<name>: { vm: { … } }` (the only accepted shape) and remove the
now-dead `findOrCreateMapEntry` helper.
