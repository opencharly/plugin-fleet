# 2026.330.2259 — fix(deploy): reset can remove an entry the loader dropped

## Summary

`charly deploy reset <box>` could not remove an entry the LOADER had dropped (a pod body written with
no `image:`). The entry is absent from the loaded `DeployConfig`, so the loaded-side mutation printed
`No overrides for box "…"` and exited 0 — a silent no-op — while the entry sat in the file and made
`SaveDeployConfig`'s round-trip guard refuse **every** later write. The only escape was
`charly deploy reset` with no box, which deletes the whole file.

The fix removes the raw top-level key from the config's YAML node form — precisely that one entry,
leaving the good entries and the config's other sections intact — with a guard so a box named after a
reserved section (`cache`, `provides`, `ledger`, `system`, `defaults`) can never delete that section.
