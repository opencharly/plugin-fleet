# 2026.240.0756 — fix(fleet): classify bare remote refs by caller kind (--add-candy candy, primary box)

## Summary

The candy de-submodule cutover changed candy refs from the in-repo subpath form (`@github.com/opencharly/charly/candy/uv:v...`) to the standalone bare form (`@github.com/opencharly/layer-uv:v...` — no `candy/<name>` subpath). `resolveRemoteRef` hardcoded bare remote refs to `RefKindBox`, so `charly fleet add --add-candy @github.com/opencharly/layer-uv:v...` misclassified every standalone candy as a box and rejected it with `remote image refs are not supported by fleet add`.

This fix threads the caller's `preferKind` into `resolveRemoteRef`: a bare remote ref now defaults to **candy** for `--add-candy` and **box** for the primary `<ref>` (unchanged behavior for the primary path — the existing `TestResolveDeployRef_RemoteSubpath` bare-repo→box case still passes).

2 files changed, +40/−5.
