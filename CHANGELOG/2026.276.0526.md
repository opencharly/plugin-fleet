# 2026.276.0526 — fix(deps)!: adopt the typed ExtraCandyRef (spec#188 consumer)

## Summary

Adopts `spec v0.2026273.203` + `sdk v0.2026276.48`, which is the type change `spec#188` made: an `ExtraCandyRef` now carries its **SCOPE**, so `spec.DeployCompileRequest.ExtraCandyRefs` is `[]spec.ExtraCandyRef{Ref, Scope}` instead of `[]string`.

**Why this repo is in the wave.** Every compiled-in plugin candy is a `require` pin in charly's `go.mod`, resolved from the module proxy, so when `sdk`'s own main moved its `spec` require to `v0.2026273.203` (`sdk#325`, merged), any charly that adopts that sdk stops compiling this candy. `plugin-build`, `plugin-fleet` and `plugin-installstep` are the three; this is the `plugin-fleet` leg.

**The change.**

1. **`dispatch.go` (+5/−2)** — this repo constructs add_candy refs, so it is the one that has to decide what their scope is — and a constant would be the `#739` collision:
   - the **candy shape** composes *into* the box the deploy creates, whose name is `ref.Name` (the compile returns the box view name; candy-ref units keep `ref.Name`) → `spec.BoxScope(ref.Name)`;
   - the **add-candy-on-box shape** adds its overlay *onto* the primary base box → `spec.BoxScope(baseBoxRef)`. `baseBoxRef` is a parameter of `compileAddCandyOnBox`, so this scope is derived from the request and is never a constant — exactly what the `#739` guard asks for.
   - The refs' scopes were previously not carried at all (a bare string); the constant-scope collision was not yet expressible, and this change is what keeps it from becoming expressible now that the field exists.
2. **`compile.go` (+1/−1)** — one line, the `fetchResolvedProject` signature (`:227`), typed `[]string → []spec.ExtraCandyRef`. That single change resolves **both** of the errors the compiler reports against this file (§2.1), because the second is the struct literal that the signature feeds.
3. **`from_box_vm_test.go` (+31/−2)** — this repo's own live-loader test is made deterministic in-tree. It already skipped when no `charly` was on `PATH`, but it **failed** when a `charly` was present and simply too old to read the schema this checkout emits — a `FATAL` where the stated intent (the test's own comment: *"a bare `go test` on a machine without charly skips rather than fails"*) and R4's live-or-skip rule both call for a **visible skip**. See §2.3.
