# 2026.318.2141 — fix(deploy): carry the resolved box into prepare-venue for a ref-based deploy

## Summary

`charly deploy add <name> <box>` fails at venue prep whenever `<name>` is not the box:

```
$ charly -C distro-fedora deploy add openwebui-lab openwebui --disposable
charly: error: command "deploy": deploy-dispatch add: deploy plugin: deploy-dispatch add: prepare venue:
  InvokeProvider deploy:pod op=prepare-venue: rpc error: code = Unknown desc =
  plugin-deploy-pod prepare-venue: overlay build: resolving "openwebui-lab" via charly.yml: not found
```

**Mechanism.** A REF-based deploy dispatch carries **no node** (`charly/unified_targets.go`:
*"node … nil for a ref-based deploy"*). This dispatch built its PrepareVenue extras from the node only:

```go
extra := map[string]any{"opts": opts}
if req.Node != nil { extra["image"] = req.Node.Image }
```

so a ref-based deploy sent **no image at all**, and the substrate fell back to the deploy KEY — handing a key
to a box resolver, which by definition cannot resolve it. For a *fresh* add the key→box lookup has nothing to
find either, because the per-host entry does not exist yet.

**Fix.** The plans the operator's ref was resolved into already carry the box — `InstallPlan.Box` is
documented as *"deployable box name (or candy name for single-candy deploys)"*. The extras now come from ONE
decision point, `prepareVenueExtras`: dispatch-merged node image → first non-empty `InstallPlan.Box` →
unset (the substrate's own fallback).

Refs plugin-deploy-pod#51 (RCA: the resolver's silent third branch + this missing input).
