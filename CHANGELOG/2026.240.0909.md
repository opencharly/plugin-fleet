# 2026.240.0909 — fix(fleet): classify a bare remote layer-* primary ref as candy

## Summary

The candy de-submodule cutover's standalone repos dropped the `candy/<name>` subpath, so a **remote PRIMARY layer ref** (`@github.com/opencharly/layer-<name>:v...`) defaulted to `RefKindBox` (the primary resolver is box-first, `preferKind=Box`) and `compileRefSelection` rejected it as a `remote image refs are not supported by fleet add`. This is the **fleet-add remote-primary-candy gap** (todo #34): the check-* R10 bed fixtures (`charly-check`, `check-local-layer`, `check-stack-layer`) cannot advance to standalone repos while their primary refs are rejected — `refs_sweep_test.go` exempts them with the comment *"check-* R10 bed fixtures stay in-repo (fleet-add gap)"*.

**Fix:** `resolveRemoteRef` now classifies a bare `layer-*` repo as `RefKindCandy` **regardless of the caller's preferred kind**, so a remote primary layer ref reaches the candy compile branch (which already allows remote candy through — the rejection is remote-BOX-only). Non-layer bare repos stay box-first for the primary path (unchanged).

2 files changed, +45/−3.
